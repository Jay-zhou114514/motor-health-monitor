- 触发：装载模块建成后，对 PRONOSTIA 的 N（记录总数）做复核，发现先前的计数口径有误。

## 1. 两处更正（均由"先验证、不假设"抓出）

### 1.1 PRONOSTIA 的分隔符不一致

镜像内绝大多数 CSV 用**逗号**，但 **`Full_Test_Set/Bearing1_4/` 使用分号**：

```text
8;8;0;4.2504e+05;0.065;-0.058
```

处理：按首行**自动识别分隔符**（模块 `runtofailure_data.read_pronostia_csv`）。

### 1.2 PRONOSTIA 的 N 计数口径错误

部分轴承目录**同时包含** `acc_*.csv`（振动）与 `temp_*.csv`（温度）。
先前的 N 按"全部 CSV"统计，**把温度文件算进了寿命**。

| 轴承 | 先前 N（错） | 正确 N（仅 `acc_*.csv`） | 温度文件数 |
| --- | ---: | ---: | ---: |
| `Full_Test_Set/Bearing1_4` | 1665 | **1428** | 237 |
| `Full_Test_Set/Bearing2_4` | 876 | **751** | 125 |
| `Learning_set/Bearing1_1` | 2803 | 2803 | 0 |

**影响**：N 偏大 → H/N 偏小 → 纳入判定偏宽松。更正后重新计算，结论未变（见 §2），
但**所有 N 与 H 必须以脚本输出为准**（`outputs/r2f_inclusion.csv`）。
XJTU-SY 只有一种文件类型，其 N 不受影响。
