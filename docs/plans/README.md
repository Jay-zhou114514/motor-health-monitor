# 研究计划版本管理（固定命名逻辑）

## 1. 固定工作流

```text
实验完成 → 分析结果 → 更新研究计划版本 → 决定下一实验
```

任何一步都不能跳过：没有"实验完成"就不能改计划；没有"结果分析"就不能定下一实验。

## 2. 实验编号规则

```text
EXP-<阶段>-<两位序号>      例如 EXP-V1-04
```

- 编号按**首次登记**的顺序分配，**永不复用、永不重排**。
- 实验注册表：`experiments/README.md`（名称、状态、脚本、结果文件）。
- 一个实验 = 一份记录（`.md`）+ 至少一份结果文件（`.csv`）。
- 记录必须包含：契约（Hypothesis / Dataset / Train / Test / Method / Metrics / Rule）、
  结果、Observation、Interpretation、Limitation。
- **不允许把 Interpretation 写成 Observation。**

## 3. 计划版本规则

- 文件命名：`RESEARCH_PLAN_v<major>.<minor>.md`。
- 每完成一个关键实验并完成结果分析后，`minor` 版本号 +1。
- 每次更新必须同时产出 `CHANGELOG.md` 中的一条记录，分类为：
  **保留 / 删除 / 修改 / 新增 / 延后 / 因实验结果而改变**。
- 重大方向调整（例如更换研究问题）才提升 `major` 版本。

## 4. 每个版本必须回答的六件事

1. 已确认事实（哪些结论已有实验支持）
2. 被否定/弱化的假设（哪些解释已被证伪或必须降级）
3. 当前最可信机制（现阶段证据最支持什么）
4. 当前最大风险（审稿人最可能质疑什么）
5. 下一实验及理由（为什么做这个，而不只是"做什么"）
6. 论文故事版本（当前证据下论文该如何表述）

## 5. 证据强度分级（防止过度解读）

| 等级 | 含义 |
| --- | --- |
| A | 在本数据集内已被受控实验证实 |
| B | 与现有证据一致，但需要更多数据/实验确认 |
| C | 尚未成立（例如置信区间重叠、无法排除随机波动） |
| D | 完全未知（跨数据集、真实设备） |

写结论时必须标注等级；等级 C/D 的内容不能写进 Abstract 或 Conclusion。

## 双线论文计划（独立仓库）

会议线 / 期刊线的计划、状态、论文骨架与投稿门槛放在独立仓库，便于命名区分与完整性维护：

<https://github.com/Jay-zhou114514/motor-health-monitor-papers>

- `conference-track/`：会议线（最小完整闭环）
- `journal-track/`：期刊线（机制验证、稳健性、跨数据集、真实实验）
- `shared/`：共享决策门、同步规则、伦理与版本模板

Master 仓库仍是唯一事实来源；论文仓库只引用 Master 中已冻结的实验结果。




## 桌面同步命名

导出到桌面时统一使用「中文名 + 版本号」，不加英文前缀：

- `研究计划_V1.3.md`
- `会议线计划_V1.2.md`
- `期刊线计划_V1.2.md`
- `固定工作流.md`
- `研究计划变更记录.md`
