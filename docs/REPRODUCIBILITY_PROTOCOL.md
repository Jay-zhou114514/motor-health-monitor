# 可复现性验证规范（Re-run Verification Protocol）

- 版本：v1.0
- 日期：2026-09-18
- 状态：**强制**。任何实验在标记"已完成"之前必须通过本规范的三层验证。
- 触发原因：EXP-V1-11 / V2-02 / V2-03 / V2-04 期间累计出现 **6 次**"假设被验证推翻"的错误
  （通道识别 ×2、传闻式排除、分隔符、N 计数口径、判定实现缺陷 ×2）。
  这些错误都不是靠"再看一遍"发现的，而是靠**独立复算**发现的。

## 三层验证（成本递增，全部必做）

### L1 不变量检查（秒级）

对每个结果 CSV 强制检查：

| 检查 | 期望 |
| --- | --- |
| 误报率/指标取值域 | ∈ [0, 1]（或按定义的范围） |
| 缺失值 | 指定列无 NaN |
| 训练量一致性 | 实际 n_train ≤ 可用池大小；k_bearings ≤ 该折可用轴承数 |
| 折数完整性 | 折数 = 预期（leave-one-bearing-out → 折数 = 纳入轴承数） |
| 重复次数 | 每格 R 与预注册一致 |
| 退化格显式标记 | SD = 0 / n_eff = ∞ 等退化情形必须被标记，**不得静默参与统计** |
| 分组键不丢失 | 汇总表必须保留实验条件的全部标识（曾因 `tag` 被覆盖而丢失"规则"维度） |

### L2 独立复算（分钟级）

用**与主脚本不同的一条代码路径**重算全部头条数字，并逐项比对：

1. 从头条表格反查原始 CSV，用独立的 groupby / 公式重算；
2. 特征层抽检：随机抽 3 条记录，**直接重读源文件**、独立实现特征公式，
   与缓存中的特征比对（容差 1e-9）；
3. 复算结果与主脚本输出**逐项一致**方可放行；
4. 发现不一致 → 记录差异、定位原因、写修订，**不得直接改数**。

### L3 确定性重跑（小时级）

1. 重新运行实验脚本（使用相同参数），生成到**新的输出目录**；
2. 对关键 CSV 计算 **SHA-256**，与归档版本逐字节比对；
3. 比对通过 → 记录哈希；
4. 不通过 → **视为可复现性缺陷**，必须定位（常见原因：Python `hash()`、
   未固定的随机种子、字典顺序、并行归约顺序、浮点归约差异）。

**注意**：随机种子必须使用跨进程确定的值（如 `zlib.crc32`），
**禁止**使用 Python 内建 `hash()`（受 `PYTHONHASHSEED` 影响、每进程不同）。

## 归档要求

每次实验除五件套（记录 / 脚本 / CSV / 日志 / 图）外，须额外归档：

- `*-hashes.txt`：关键 CSV 的 SHA-256；
- L1/L2 的执行输出（附在实验记录中）；
- L3 的重跑结论（通过 / 不通过 + 哈希）。

## 与既有流程的关系

本规范插入到既有工作流中，位置为：

```text
实验完成 → 【L1 不变量 → L2 独立复算 → L3 确定性重跑】→ 结果审查 → 假说判定
        → 风险审查 → 更新研究路线 → 发布新版本
```

**未通过三层验证的实验不得进入结果审查。**
